PulseWave AI Support

A customer support and RMA assistant for three products that answers only from their manuals, so customers get verifiable help instead of generic or invented steps.

About me

Hi, I am YOUR NAME, an embedded systems engineer moving into AI engineering. I build things that must work reliably on constrained hardware, and I brought that mindset here: small footprint, clear failure states, no guessing.

The problem

Support bots give generic answers, and plain LLMs invent features or unsafe troubleshooting steps.

The approach

Retrieve passages from the real manuals, answer only from them, and cite the source.

One knowledge base, three products

Airdopes Apex

Earbuds manual: pairing, touch controls, Beast Mode, care, reset and RMA.

Stone Spark

Speaker manual: TWS, AUX and microSD modes, IPX7 rules, reset and RMA.

StormCall Plus

Smartwatch manual: app binding, calling, health sensors, restart, reset and RMA.

All three manuals share the same seven-chapter structure and are embedded into one pgvector collection, so a single question can be matched to the right product and section.

How a question becomes an answer

  1. 1. QuestionBrowser posts JSON to /chat.
  2. 2. EmbedFastEmbed creates a vector locally.
  3. 3. Retrievepgvector returns the closest manual passages.
  4. 4. GuardLangGraph checks context. No match means no guess.
  5. 5. AnswerGemini Flash replies from that context with sources.

Messages that contain a serial number skip the manuals and go to the warranty and RMA records instead. A ticket is only created when the order ID matches.

Engineering decisions

Grounded retrieval, not model memory

RAG over Supabase pgvector ties answers to manufacturer manuals.

Decoupled API

A typed FastAPI /chat endpoint can be tested alone or plugged into a CRM or ticketing system.

Graceful failure

HTTP 429, timeouts and offline servers each get a clear message and a retry button.

Lean footprint

Local FastEmbed baked into the Docker image avoids slow cold starts and keeps memory low.

Verifiable answers

Each reply lists the manual sections it used.

Safe by default

Output is rendered as text, never HTML. Record tables use row level security and return no customer data.

Tech stack
